# 梦魇：无归 Modkit 技术实现文档

本文记录当前 `nwr_modkit` 的有效实现。旧版 DQ2 路线已经不作为依据；本项目按《梦魇：无归》的真实文件格式重新整理。

## 当前原则

- 不修改游戏根目录 `package.json`。
- 不修改 `www/index.html`。
- 不直接覆盖 `www/save` 原始存档，除非用户手动导出并替换。
- 运行时 GUI 修改器路线暂时保留为实验路线；当前主方案是独立存档编辑器。

## 目录说明

```text
nwr_modkit/
  app/save-editor/          独立存档编辑器，浏览器里打开
  tools/save-codec.mjs      存档解码/编码
  tools/data-codec.mjs      www/data/*.json 解密/加密
  tools/probe-data-key.mjs  数据密钥复验脚本
  docs/                     当前文档
  output/                   工具输出目录
  runtime/                  运行时实验和历史探针
```

## 存档格式

当前游戏的 `www/save/*.rpgsave` 不是 AES/HMAC 加密格式，也没有单独的存档密钥。

真实流程是：

```text
.rpgsave 文本
  -> LZString.decompressFromBase64
  -> 得到一段 base64 字符串
  -> Buffer.from(base64, "base64")
  -> zlib.inflateSync
  -> JSON.parse
```

写回流程反向执行：

```text
JSON.stringify
  -> zlib.deflateSync
  -> 转 base64
  -> LZString.compressToBase64
  -> .rpgsave 文本
```

实现位置：

```text
nwr_modkit/tools/save-codec.mjs
```

这就是为什么现在的存档编辑器可以直接按 JSON 原生结构展示和修改，而不需要“存档 key”。

## 数据 JSON 加密

`www/data/*.json` 文件名虽然是 `.json`，但磁盘内容多数是十六进制密文。例如 `System.json`、`Actors.json`、`MapInfos.json` 都不是明文 JSON。

本次重新复验得到的数据解密参数如下：

```text
algorithm: aes-192-cbc
password:  6f03e16e201226059d4aaa5e1950da4a
salt:      2023/3/19
keyLength: 24
keyHex:    eda0337069573a14c302c58324416304580b3a7e515133ab
ivHex:     01010101010101010101010101010101
```

推导方式：

```js
crypto.scryptSync("6f03e16e201226059d4aaa5e1950da4a", "2023/3/19", 24)
```

得到：

```text
eda0337069573a14c302c58324416304580b3a7e515133ab
```

实现位置：

```text
nwr_modkit/tools/data-codec.mjs
```

## 密钥复验过程

新增脚本：

```text
nwr_modkit/tools/probe-data-key.mjs
```

复验命令：

```powershell
node .\nwr_modkit\tools\probe-data-key.mjs --game-root .
```

本次复验结果摘要：

```json
{
  "algorithm": "aes-192-cbc",
  "source": "scrypt-password-salt",
  "keyHex": "eda0337069573a14c302c58324416304580b3a7e515133ab",
  "ivHex": "01010101010101010101010101010101",
  "matchesKnownKey": true
}
```

脚本同时成功解开：

```text
www/data/System.json   object, 55 keys
www/data/Actors.json   array, 71 entries
www/data/MapInfos.json array, 859 entries
```

这一步不启动 `Game.exe`，也不进入游戏主菜单；它直接读取磁盘上的 `www/data/System.json` 并解密。因此可以确认：这组参数属于数据加载阶段，至少在游戏正式进入场景前就必须可用。

历史运行时探针也记录过同一条链路：

```text
nwr_modkit/runtime/save-harness/probe-result.json
```

其中能看到 `crypto.scryptSync` 的输入：

```text
password = 6f03e16e201226059d4aaa5e1950da4a
salt     = 2023/3/19
```

以及输出 key：

```text
eda0337069573a14c302c58324416304580b3a7e515133ab
```

现在的 `probe-data-key.mjs` 等于是把这个运行时结果离线重放，并用真实 `System.json` 验证。

## scrypt 判断依据和重新抓取

`scrypt` 不是通过静态猜测得出，而是由运行时探针 hook 到的真实调用。

使用的探针工具：

```text
nwr_modkit/runtime/save-harness/index.html
```

探针会在游戏脚本加载阶段包一层 Node crypto 相关函数，重点记录：

```text
crypto.scryptSync(...)
crypto.createDecipheriv(...)
```

输出文件：

```text
nwr_modkit/runtime/save-harness/probe-result.json
```

关键记录如下：

```text
scryptSync(
  password = 6f03e16e201226059d4aaa5e1950da4a,
  salt     = 2023/3/19,
  keylen   = 24
)

return:
eda0337069573a14c302c58324416304580b3a7e515133ab
```

随后同一份 trace 里又记录到：

```text
createDecipheriv(
  algorithm = aes-192-cbc,
  key       = eda0337069573a14c302c58324416304580b3a7e515133ab,
  iv        = 01010101010101010101010101010101
)
```

因此推断链路是：

```text
password + salt
  -> crypto.scryptSync(password, salt, 24)
  -> AES-192-CBC key
  -> crypto.createDecipheriv("aes-192-cbc", key, iv)
  -> 解 www/data/*.json
```

可以用 Node 直接重算：

```powershell
node --input-type=module -e "import crypto from 'node:crypto'; console.log(crypto.scryptSync('6f03e16e201226059d4aaa5e1950da4a','2023/3/19',24).toString('hex'))"
```

期望输出：

```text
eda0337069573a14c302c58324416304580b3a7e515133ab
```

如果要重新跑运行时抓取：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\nwr_modkit\tools\setup-runtime.ps1 -GameRoot .

Remove-Item .\nwr_modkit\runtime\save-harness\probe-result.json -Force -ErrorAction SilentlyContinue

$h = (Resolve-Path .\nwr_modkit\runtime\save-harness).Path
Start-Process -Wait -FilePath "$h\Game.exe" -WorkingDirectory $h

rg -n "scryptSync|createDecipheriv|6f03e16e201226059d4aaa5e1950da4a|2023/3/19|eda0337069573a14c302c58324416304580b3a7e515133ab|aes-192-cbc" "$h\probe-result.json"
```

这条运行时抓取链路和 `probe-data-key.mjs` 的离线复验链路互相验证：前者说明游戏实际调用了什么，后者说明这组参数确实能解开真实数据文件。

## 素材加密 Key

解密后的 `System.json` 里还有 RPG Maker MV 自带素材加密字段：

```text
hasEncryptedImages: true
hasEncryptedAudio:  true
encryptionKey:      c8837b23ff8aaa8a2dde915473ce0991
```

注意：这把 `encryptionKey` 是图片/音频素材的 RPG Maker 加密 key，不是 `www/data/*.json` 的 AES-192-CBC key，也不是存档 key。

## 数据提取和回包

提取 `www/data/*.json` 到明文目录：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\nwr_modkit\tools\extract-data.ps1 -GameRoot .
```

默认输出：

```text
nwr_modkit/output/extract/data/
```

重新加密明文 JSON：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\nwr_modkit\tools\encrypt-data.ps1
```

默认输出：

```text
nwr_modkit/output/repack/data/
```

这些命令默认只写 `nwr_modkit/output`，不会自动覆盖原游戏 `www/data`。

## 存档编辑器路线

存档编辑器位于：

```text
nwr_modkit/app/save-editor/
```

启动脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\nwr_modkit\tools\launch-save-editor.ps1
```

默认地址：

```text
http://127.0.0.1:5176/
```

编辑器的核心逻辑是读取 `.rpgsave`、按原生 JSON 结构展示、修改后再用同一套编码写出。它不需要注入游戏窗口，也不依赖运行时 GUI。

## 根目录解析

工具优先按以下顺序查找游戏根目录：

1. 命令行传入的 `--game-root` 或 PowerShell 的 `-GameRoot`。
2. 环境变量 `NWR_GAME_ROOT`。
3. 兼容旧脚本的 `DQ2_GAME_ROOT`。
4. `nwr_modkit/config.local.json` 里的 `gameRoot`。
5. `nwr_modkit` 的父目录。

推荐当前布局就是：

```text
Nightmare without return/
  www/
  nwr_modkit/
```

这种情况下大多数命令直接在游戏根目录执行即可。
