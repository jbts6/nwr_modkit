# 技术实现文档

本文面向维护者，说明 `nwr_modkit` 的文件格式、运行时 bridge、数据索引、生成目录和验证方式。用户操作流程见 [工具使用说明](工具使用说明.md)。

## 设计边界

项目遵守以下边界：

- 不修改游戏根目录的 `package.json`。
- 不修改 `www/index.html`。
- 不直接覆盖 `www/save`。
- 不把游戏本体、运行时 DLL/EXE/PAK、解密输出、存档、日志或本地配置提交到仓库。
- 需要写回游戏目录的操作由用户手动完成，并且应先备份原文件。

运行时修改器通过生成一个独立的 bridge 版游戏目录工作。原游戏目录保持不变。

## 目录职责

```text
nwr_modkit/
  app/gui/                 NW GUI 修改器
  app/save-editor/         React/Vite 离线存档编辑器
  runtime/bridge/          注入游戏页面的 bridge 脚本
  runtime/bridge-state/    bridge 命令、状态和日志，生成目录
  runtime/game-app/        手动 bridge 游戏目录，生成目录
  runtime/save-harness/    存档/数据探针 harness
  tools/                   PowerShell 入口和 Node 脚本
  output/extract/          解包/解密输出，生成目录
  output/repack/           回包/重新加密输出，生成目录
  output/backup/           GUI 备份目录，生成目录
  docs/                    文档
```

`app/gui/app.ts` 是 GUI 源码，`app/gui/app.js` 是构建产物，但 NW 运行时直接加载 `app.js`，因此仓库保留这份文件。

`app/save-editor/public/game-data-index.json` 是由本地游戏数据生成的查找索引，已被 `.gitignore` 忽略。

## 游戏根目录解析

PowerShell 和 Node 工具使用同一套解析顺序：

1. 命令行参数：`-GameRoot` 或 `--game-root`。
2. 环境变量：`NWR_GAME_ROOT`。
3. 兼容环境变量：`DQ2_GAME_ROOT`。
4. `config.local.json` 里的 `gameRoot`。
5. `nwr_modkit` 的父目录。

有效游戏根目录必须包含：

```text
www/index.html
```

推荐布局：

```text
Nightmare without return/
  Game.exe
  www/
  nwr_modkit/
```

## 存档格式

`www/save/*.rpgsave` 不使用 AES，也没有 HMAC。编码流程是：

```text
.rpgsave 文本
  -> LZString.decompressFromBase64
  -> base64 字符串
  -> Buffer.from(value, "base64")
  -> zlib.inflateSync
  -> JSON.parse
```

写回流程反向执行：

```text
JSON.stringify
  -> zlib.deflateSync
  -> base64
  -> LZString.compressToBase64
  -> .rpgsave 文本
```

实现文件：

```text
tools/save-codec.mjs
app/save-editor/src/codec.ts
```

脚本侧和浏览器侧各有一份实现。修改格式逻辑时，两边需要保持一致。

## 数据 JSON 加密

`www/data/*.json` 的文件名是 `.json`，但磁盘内容通常是十六进制密文。数据文件使用 AES-192-CBC：

```text
algorithm: aes-192-cbc
password:  6f03e16e201226059d4aaa5e1950da4a
salt:      2023/3/19
keyLength: 24
keyHex:    eda0337069573a14c302c58324416304580b3a7e515133ab
ivHex:     01010101010101010101010101010101
```

key 的推导方式：

```js
crypto.scryptSync("6f03e16e201226059d4aaa5e1950da4a", "2023/3/19", 24)
```

实现文件：

```text
tools/data-codec.mjs
```

`parseDataFileText` 同时支持明文 JSON 和加密十六进制文本，方便工具读取 `output/extract/data` 或原始 `www/data`。

RPG Maker 素材加密 key 位于解密后的 `System.json`：

```text
c8837b23ff8aaa8a2dde915473ce0991
```

这把 key 用于图片/音频素材，不用于 `www/data/*.json`，也不是存档密钥。

## 数据提取和回包

明文提取：

```powershell
.\tools\extract-data.ps1 -GameRoot ..
```

输出：

```text
output/extract/data/
output/extract/data/_extract-report.json
```

重新加密：

```powershell
.\tools\encrypt-data.ps1
```

输出：

```text
output/repack/data/
output/repack/data/_repack-report.json
```

这些命令只写 `output/`，不会直接覆盖游戏目录。

## 保存编辑器索引

结构化存档编辑需要变量、开关、物品、技能、角色、职业和地图名称。索引由本地游戏数据生成：

```powershell
node .\tools\build-save-editor-index.mjs --game-root ..
```

默认输出：

```text
app/save-editor/public/game-data-index.json
```

字段包括：

```text
switches
variables
actors
items
weapons
armors
skills
classes
maps
```

`launch-save-editor.ps1` 会在启动前刷新索引。索引缺失时，前端不会报错，而是退回 ID 显示。

## 运行时 bridge

运行时修改器使用手动 bridge 目录：

```text
runtime/game-app/
```

准备流程：

```powershell
.\tools\launch-runtime.ps1 -BgBridgeManual
```

或在 GUI 中点击 `准备桥接`。

准备脚本会复制/链接 NW 运行时文件，生成手动启动脚本，并把 bridge 注入游戏页面启动流程。原始游戏目录不被改写。

bridge 页面脚本：

```text
runtime/bridge/page-bridge.js
```

GUI 期望的 bridge 版本记录在：

```text
app/gui/app.ts
app/gui/protocol-metadata.json
tools/launch-bg-bridge-runtime.ps1
```

更新 bridge 协议时，需要同步这些版本号，并运行协议测试。

## bridge 状态和命令

bridge 使用文件队列和状态文件通信：

```text
runtime/bridge-state/
  state.json
  commands/
  results/
  bridge.log
```

典型方向：

```text
GUI 或 CLI
  -> 写入命令
  -> bridge 轮询并执行
  -> bridge 写回结果和 state.json
```

CLI 入口：

```powershell
node .\tools\trainer-send.mjs --help
```

GUI 的命令构建逻辑在：

```text
app/gui/src/bridge-commands.ts
app/gui/src/command-guardrails.ts
app/gui/src/bridge-io.ts
```

运行时状态解析在：

```text
app/gui/src/runtime-state.ts
```

## GUI 数据目录

GUI 的长列表来自解密后的数据索引。启动脚本会检查并生成：

```text
output/extract/data/
```

如果 `www/data` 来自 `data.pak` 或其它打包布局，相关脚本会走对应提取路径。GUI 不应该直接依赖仓库里存在明文游戏数据。

## 小黑屋护栏

小黑屋护栏来自解密后的 `CommonEvents.json`、`System.json` 和地图事件枚举。核心惩处开关是：

```text
Switch 520: 【破坏规则惩处】
```

直接传送目标：

```text
Map 695: 监禁小屋
坐标: 4,4
```

公共事件分为两类：

```text
直接提示并传送 Map695：
  CE334
  CE337
  CE338
  CE339
  CE340
  CE341
  CE342
  CE343
  CE344
  CE405

只设置惩处开关或相关判定开关：
  CE335
  CE336
  CE403
  CE406
  CE407
  CE571
  CE572
```

相关副作用开关：

```text
Switch166
Switch781
Switch784
Switch785
Switch1067
```

运行时和离线编辑器共用同一套规则语义：

```text
app/save-editor/src/prisonGuards.ts
runtime/bridge/page-bridge.js
app/gui/src/prison-guard-view.ts
app/gui/tests/prison-guard-contract.mjs
```

离线可自动修复的风险包括数量阈值、金币/积分阈值、功勋变量、`Switch520` 和若干“角色在队伍中但缺关键物品”的组合。

`CE344` 使用 `actor(2).param(9)`，该值依赖运行时公式、装备和插件效果。离线存档编辑器只能提示，不能完全证明或自动修复。

## 存档护栏行为

存档编辑器导入存档或 JSON 后会生成 `PrisonGuardReport`。导出 `.rpgsave` 前会重新检查。如果命中硬风险，导出会被拒绝。

一键修复会把数值压到阈值以下，或补齐关键物品。它不会从队伍中移除角色。

运行时 GUI 的 `修复可修复项` 通过 bridge 发送命令，作用于当前运行中的游戏状态。

## 运行时生成文件

生成目录和文件由 `.gitignore` 管理：

```text
node_modules/
app/save-editor/dist/
app/save-editor/public/game-data-index.json
runtime/game-app/
runtime/bridge-state/*
runtime/*-profile*/
output/extract/*
output/repack/*
output/backup/*
NW 运行时 DLL/EXE/PAK/DAT/BIN/JSC
```

清理：

```powershell
.\tools\clean-runtime.ps1
```

连依赖一起清理：

```powershell
.\tools\clean-runtime.ps1 -IncludeDependencies
```

`output/repack` 和 `output/backup` 可能包含用户需要的结果。清理脚本默认不会删除这些目录里的文件。

## 修改建议

- 改 bridge 命令时，同步更新 CLI、GUI 命令构建器、bridge 处理逻辑和协议测试。
- 改小黑屋规则时，同步更新存档编辑器、bridge、GUI 提示和 `prison-guard-contract.mjs`。
- 改数据格式时，同步更新 `tools/` 和浏览器端实现。
- 添加生成目录时，先更新 `.gitignore`，再补 `.gitkeep` 或清理脚本。
- 文档应描述稳定的使用方式和维护约定，不写排查日志或提交记录。
