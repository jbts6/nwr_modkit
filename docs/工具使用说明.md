# 工具使用说明

本文面向普通使用者，说明 `nwr_modkit` 里每个入口脚本的用途和常见操作。命令默认在 `nwr_modkit` 目录执行。

如果文档里的命令使用相对路径，请先进入工具目录：

```powershell
cd "<游戏目录>\nwr_modkit"
```

推荐目录布局：

```text
Nightmare without return/
  Game.exe
  www/
  nwr_modkit/
```

这种布局会自动把 `nwr_modkit` 的父目录识别为游戏目录。

## 基础准备

检查 Node.js：

```powershell
node --version
npm.cmd --version
```

如果没有 Node.js，可以安装 LTS 版：

```powershell
winget install -e --id OpenJS.NodeJS.LTS
```

PowerShell 如提示禁止运行脚本，可以使用单次绕过：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\tools\launch-gui.ps1"
```

也可以设置当前用户策略：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

如果工具目录不在游戏目录下，配置游戏路径：

```powershell
Copy-Item .\config.example.json .\config.local.json
notepad .\config.local.json
```

配置示例：

```json
{
  "gameRoot": "D:\\Games\\Nightmare without return"
}
```

也可以临时设置环境变量：

```powershell
$env:NWR_GAME_ROOT = "D:\Games\Nightmare without return"
```

## 启动运行时 GUI 修改器

```powershell
.\tools\launch-gui.ps1
```

首次启动会自动安装 GUI 依赖、构建 `app/gui/app.js`，并准备需要的运行时文件。默认 npm registry 是 `https://registry.npmmirror.com`。

指定 npm registry：

```powershell
.\tools\launch-gui.ps1 -NpmRegistry "https://registry.npmmirror.com"
```

也可以用环境变量：

```powershell
$env:NWR_NPM_REGISTRY = "https://registry.npmmirror.com"
```

GUI 启动后的流程：

1. 保留默认启动方式 `Prepare manual bridge game`。
2. 点击 `准备桥接`。
3. 等待 `准备游戏` 状态变成 `已准备`。
4. 点击 `打开游戏`。
5. 游戏窗口出现后等待 GUI 状态变成 `已连接`。

也可以手动打开：

```text
runtime/game-app/start-manual-bg-bridge.cmd
```

注意：运行时 GUI 只能连接准备好的 bridge 版游戏。普通根目录 `Game.exe` 已经打开后，GUI 不能再后附加进去。

## 运行时 GUI 功能

GUI 功能以界面面板为准，常见入口如下：

```text
常用
  金币/积分
  经验倍率
  掉率倍率
  小黑屋护栏
  存档/标题刷新

物品角色
  物品
  武器
  防具
  技能
  角色编辑

世界
  地图传送
  公共事件
  诊断

战斗
  战斗状态辅助
```

部分命令需要游戏已经进入可操作场景。地图、公共事件、战斗相关命令依赖当前场景状态，如果 GUI 提示当前面板不可用，请先进入地图或战斗后再试。

## 小黑屋护栏

GUI 的 `常用 -> 小黑屋` 会读取运行时 bridge 状态，检查已知的小黑屋风险。

可用操作：

```text
刷新检测
修复可修复项
查看小黑屋触发条件
```

`修复可修复项` 会处理已知的离线硬阈值和关键物品组合，包括：

```text
Switch520【破坏规则惩处】
至尊魔戒
传说的灵魂结晶
红色萃取精华
橙色萃取精华
金币/积分
功勋变量
浮世绘卷
针剂进化次数
全面进化针剂
若干角色在队伍中但缺关键物品的组合
```

`actor(2).param(9)` 是运行时公式、装备和插件共同计算的角色参数。GUI 会提示风险，但不会自动改这个值。

离线诊断脚本：

```powershell
node .\tools\diagnose-prison-checks.mjs --game-root ..
```

指定存档：

```powershell
node .\tools\diagnose-prison-checks.mjs --save "..\www\save\file1.rpgsave"
```

输出 `Hits: none` 表示没有命中已知离线阈值。

## 启动离线存档编辑器

```powershell
.\tools\launch-save-editor.ps1
```

默认地址：

```text
http://127.0.0.1:5176/
```

指定端口：

```powershell
.\tools\launch-save-editor.ps1 -Port 5177
```

只启动服务，不自动打开浏览器：

```powershell
.\tools\launch-save-editor.ps1 -NoOpen
```

使用流程：

1. 点击 `打开存档`。
2. 选择 `www/save/fileN.rpgsave`、`global.rpgsave` 或 `config.rpgsave`。
3. 使用 JSON 树或简易编辑面板修改。
4. 点击 `导出存档`。
5. 备份原文件后，手动把导出的 `.rpgsave` 放回 `www/save/`。

编辑器不会直接覆盖游戏存档。建议每次编辑前备份：

```powershell
Copy-Item ..\www\save ..\www\save_backup -Recurse
```

存档编辑器启动时会尝试生成本地字段索引：

```text
app/save-editor/public/game-data-index.json
```

该文件用于显示变量、开关、物品、技能等名称和图标索引。它是本地生成物，不进入 Git。没有索引时，编辑器仍可工作，但会更多显示原始 ID。

## 存档编解码

存档格式：

```text
LZString Base64 -> zlib deflate -> JSON
```

把游戏存档导出成 JSON：

```powershell
.\tools\extract-saves.ps1 -GameRoot ..
```

默认输出：

```text
output/extract/save/
```

把 JSON 重新编码为 `.rpgsave`：

```powershell
.\tools\encrypt-saves.ps1
```

单文件编解码逻辑在：

```text
tools/save-codec.mjs
```

当前存档格式没有独立 AES 存档密钥，也没有 HMAC 校验。

## 数据 JSON 提取

`www/data/*.json` 文件名是 `.json`，但内容通常是加密十六进制文本。

提取明文数据：

```powershell
.\tools\extract-data.ps1 -GameRoot ..
```

默认输出：

```text
output/extract/data/
```

报告文件：

```text
output/extract/data/_extract-report.json
```

重新加密明文 JSON：

```powershell
.\tools\encrypt-data.ps1
```

默认输出：

```text
output/repack/data/
```

报告文件：

```text
output/repack/data/_repack-report.json
```

`encrypt-data.ps1` 不会自动覆盖原游戏 `www/data`。要替换游戏文件，请先备份原文件，再手动复制。

## 数据密钥复验

复验 `www/data/*.json` 的解密参数：

```powershell
node .\tools\probe-data-key.mjs --game-root ..
```

指定采样文件：

```powershell
node .\tools\probe-data-key.mjs --game-root .. --samples System,Skills,Items
```

显式传入 key：

```powershell
node .\tools\probe-data-key.mjs --game-root .. --key-hex eda0337069573a14c302c58324416304580b3a7e515133ab
```

数据文件参数：

```text
algorithm: aes-192-cbc
password:  6f03e16e201226059d4aaa5e1950da4a
salt:      2023/3/19
keyHex:    eda0337069573a14c302c58324416304580b3a7e515133ab
ivHex:     01010101010101010101010101010101
```

RPG Maker 素材加密 key 是另一件事：

```text
c8837b23ff8aaa8a2dde915473ce0991
```

它用于图片/音频素材，不用于 `www/data/*.json`，也不是存档密钥。

## 提取其它资源

导出 `data.pak`：

```powershell
node .\tools\extract-data-pak.mjs --game-root ..
```

导出 `useData`：

```powershell
node .\tools\extract-usedata.mjs --game-root ..
```

导出 data、useData 和存档：

```powershell
.\tools\extract-all.ps1 -GameRoot ..
```

抽取和分类 NW/V8 字节码：

```powershell
.\tools\extract-js-bytecode.ps1 -GameRoot ..
```

这些输出都写入 `output/` 或 `runtime/` 下的生成目录。

## 清理生成文件

清理运行时链接、bridge 状态、profile、解包输出和构建产物：

```powershell
.\tools\clean-runtime.ps1
```

连 `node_modules` 一起清理：

```powershell
.\tools\clean-runtime.ps1 -IncludeDependencies
```

清理脚本不会删除 `output/backup` 和 `output/repack` 里的用户输出。

## 常见问题

### GUI 连接不上

确认游戏是通过 `准备桥接` 后的 `打开游戏` 或 `runtime/game-app/start-manual-bg-bridge.cmd` 启动的。普通 `Game.exe` 不能被 GUI 后附加连接。

### 打开游戏按钮不可用

先点击 `准备桥接`。准备成功后，GUI 才会知道 `runtime/game-app/start-manual-bg-bridge.cmd` 的位置。

### 存档编辑器看不到物品名称

检查工具是否能找到游戏目录。启动脚本需要读取本地 `www/data` 来生成 `game-data-index.json`。索引缺失时编辑器会退回 ID 显示。

### PowerShell 找不到 npm

安装 Node.js 后重新打开 PowerShell，再运行：

```powershell
node --version
npm.cmd --version
```

### 命令里 `-GameRoot ..` 是什么意思

文档默认在 `nwr_modkit` 目录执行，`..` 就是游戏根目录。如果你在游戏根目录执行命令，请使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\nwr_modkit\tools\extract-data.ps1 -GameRoot .
```
