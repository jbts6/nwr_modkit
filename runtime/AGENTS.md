# RUNTIME NOTES

## OVERVIEW

Runtime bridge and probe area. `bridge/` contains the authored manual bridge injection surface; `save-harness/`, state directories, logs, bytecode, and NW runtime payloads are generated or game-derived.

## STRUCTURE

```text
runtime/
|-- bridge/              # injected page bridge surface
|-- save-harness/        # hidden NW probe/harness; mostly generated
`-- save-editor-state/   # generated state
```

## WHERE TO LOOK

| Task | Location | Notes |
| --- | --- | --- |
| Page bridge | `bridge/page-bridge.js` | Injected game-page command/state bridge. |
| Save/data key probe | `save-harness/index.html`, `save-harness/probe-result.json` | Probe result is generated. |
| Setup/launch | `../tools/setup-runtime.ps1`, `../tools/launch-*-runtime.ps1` | Runtime files are refreshed by scripts. |

## CONVENTIONS

- Runtime launcher scripts create or refresh hardlinks/junctions from the configured game root.
- `save-harness/probe-result.json` records crypto calls such as `scryptSync` and `createDecipheriv`; regenerate it rather than hand-editing.
- Bridge payload changes must stay compatible with GUI command senders in `app/gui/app.ts`.
- `runtime/bridge-state/` and save-editor state files are transient state, not source.

## ANTI-PATTERNS

- Do not edit generated NW runtime files under runtime subdirectories: `*.dll`, `*.exe`, `*.pak`, `*.dat`, `*.bin`, `*.jsc`.
- Do not treat `save-harness/node_modules/` or generated bytecode as maintained source.
- Do not use runtime probe artifacts as the only source of truth; verify codec changes with the offline scripts in `tools/`.

## COMMANDS

```powershell
.\tools\setup-runtime.ps1 -GameRoot .
.\tools\setup-runtime.ps1 -Force
.\tools\launch-runtime.ps1
.\tools\clean-runtime.ps1
```
