# GUI APP NOTES

## OVERVIEW

NW.js GUI modifier. The authored source is `app.ts`; the game-facing app loads compiled `app.js` through `index.html` and may sit beside generated NW runtime files.

## WHERE TO LOOK

| Task | Location | Notes |
| --- | --- | --- |
| Main source | `app.ts` | Single large TypeScript file for catalog, bridge, command, and UI logic. |
| Loaded app shell | `index.html`, `app.js` | `app.js` is generated from `app.ts`. |
| Build config | `package.json`, `tsconfig.json` | Only build script is `tsc -p tsconfig.json`. |
| Catalog data | `../../output/extract/data/` | Generated by extraction scripts when missing/stale. |
| Launcher | `../../tools/launch-gui.ps1` | Auto-builds when `app.ts` is newer than `app.js`. |

## CONVENTIONS

- Build with TypeScript only; there is no bundler for this app.
- NW Node globals are expected. Browser-only assumptions can break launch.
- `launch-gui.ps1` may run setup and data extraction before opening the app.
- Treat UI catalog size as large: item, skill, actor, map, troop, variable, and switch lists are paged.
- Keep bridge command payloads compatible with `runtime/bridge`.

## ANTI-PATTERNS

- Do not edit `app.js` as the primary source. Change `app.ts`, then rebuild.
- Do not edit generated NW runtime files in this directory: `*.dll`, `*.exe`, `*.pak`, `*.dat`, `*.bin`, `locales/`, `swiftshader/`.
- Do not rely on `npm test`; this package has no test script.
- Do not assume extracted catalog data exists. Launch scripts can generate it.

## COMMANDS

```powershell
cd .\nwr_modkit\app\gui
npm.cmd install --registry https://registry.npmmirror.com
npm.cmd run build

cd ..\..
.\tools\launch-gui.ps1
```
